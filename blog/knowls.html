Creating a LaTeX powered blog inspired by LMFDB - Part 2

In a previous post, I talked about creating a site generator with LaTeX support. Here, I talk about the LMFDB feature that got me to start doing this in the first place, its knowledge database.

On the LMFDB, you will find underlined words, clicking on such a word brings a popup with its definition and relevant information. They call them knowls. I'll call them definitions instead.

I can think of many ways to implement them. The simplest way, and in my mind the best, is to do something similar to what I did previously with LaTeX. Like before, I'll illustrate how it's implemented by showing what the script does to the directory structure. It goes from this


.

│   └── 2026-10-23-latex.md
├── defs
│   ├── pid.md
│   └── ufd.md
├── defs_replace.js
├── demos
│   └── ...
├── index.md

to this

├── blog
│   ├── index.html

The content of pid.md would be


Display: PID
Title: Principal Ideal Domain

An \def{integral domain} in which every \def{ideal} is \def{principal ideal, principal}.

Which works with LaTeX just fine


Since $\mathbb Z$ is a \def{pid}, it's also a \def{ufd}.

gives

Since is a PID, it's also a UFD.

If you have javascript disabled, what you will get is a link to the definition page. With javascript, clicking on the link will open a popup at the end of the paragraph, similar to how it works on LMFDB. The javascript file for turning the links into popups is only loaded on pages that have definitions. Instead of loading /defs/def/pid.html, the script loads /defs/min/pid.html, which contains no html boilerplate, saving some (small) bandwidth. Like LMFDB, if a definition is contained multiple times in a document, it will be loaded at most once.

All the definitions in the site are listed on the knowledge tab. Along with a defs.db file, which could be out of sync because of how the site generator code is right now.

With that done I'm not sure if this feature would be as useful as LaTeX support is for this blog. While this implementation leaves much to be desired compared to LMFDB's, it (along with much of this site) doesn't require javascript to function. Something I hope to see more often.
